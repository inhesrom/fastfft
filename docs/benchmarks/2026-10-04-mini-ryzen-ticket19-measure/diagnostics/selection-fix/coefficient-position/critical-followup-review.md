# Critical review of coefficient-position capture

The capture remains **invalid as performance evidence** because the whole-run quiet rule failed on one background sample. The40 per-trial audit passes and tight restoration do not waive that failure. Keep every process/sample and treat these results only as exploratory input to a fresh, fully quiet experiment. No production layout fix is accepted.

The all-coefficient1024 displacement consistently improves N4096 OOP p1 in both directions and both members (roughly2.75–4.45%) but worsens inverseIP (1.70–5.64%). Zero endpoints largely restore, and64 generally loses. This is not evidence for a blanket1KiB policy. N210 Estimate64 is essentially flat;1024 is mostly flat/slightly worse, with an isolated2%IP loss. Its unshifted Measure reference is stable. The adjacent JSON retains all per-process p1 effects and restoration ratios.

For N4096, the proposed **PhaseB-only1024** arm is the most discriminating small extension. PhaseB begins4224, has32768 bytes, and ends36992 within40960 bytes, so no new allocation is needed. Preserve every PhaseA table/descriptor pointer, move only PhaseB within initialized slack, and compare zero/PhaseB-only/all-coefficients at the same1024 displacement. Require original canonical PhaseA offsets for the PhaseB intervention; restore its offset0 before switching scopes, and reject mixed layouts. Retain both OOP directions and inverseIP. If PhaseB-only retains the OOP gain without IP harm, a narrower remedy becomes plausible. It still would not prove that PhaseA alone is bad: interaction between coefficient regions can explain the difference. A clean new capture must reproduce the all-shift arm too.

For N210, recorded geometry is strikingly consistent across all16 IP/OOP processes: Object mod4096=3232, backing/descriptors=0, cross=576, input=704, output=192, scratch=3968. Matrix/work geometry is unchanged: work1=scratch+3392 (mod4096=3264), work2=scratch+5312 (mod4096=1088). Thus this experiment tests coefficient positions against one recurring relative geometry, not a wide sample of all possible caller placements. Moving the slab leaves both descriptor prefix and plan object fixed. No hardware aliasing mechanism follows from those offsets alone.

There is now a concrete code-overhead candidate independent of coefficient loads. N21014×15 at8 lanes runs two column panels and two row panels, one full and one partial in each stage. Each panel has exactly one radix; completion executes no later Stockham pass and reads no panel twiddle table. But `complete()` still performs `.iter().enumerate().skip(1)`. With24-byte Pass descriptors, the retained current F64x8 assembly at `0xe69afa–0xe69b1a` computes remaining length via pointer subtraction, shift-right3, a load of0xaaaaaaaaaaaaaaab and IMUL before the count1 skip exit. Prior8-byte radix iteration at `0xe71dbf–0xe71dce` needs subtraction and shift-right3 only. The added constant multiplication therefore exists even in this single-pass case. Similar skip sites occur in the other full/partial and row variants.

The smallest general code control is an indexed loop `for pass in 1..panel.passes.len()` in complete(), retaining identical storage and transform choreography. A generic single-pass early return is another option, but indexed iteration addresses stride-derived iterator bookkeeping more generally. Review the compiled skip path, then measure under a fresh quiet gate with both N210 placements and larger/multipass controls. Do not infer that two added instructions explain the entire6–7% loss: entry hoisting, register allocation and code layout also changed. The assembly reviewed is retained frozen production code, not a new disassembly of this diagnostic binary.

A whole-backing64-aligned counterfactual is useful if that code control is unhelpful or if the next experiment must preserve executable code. Prepare exactly one64-aligned Block allocation with the same8192 initialized bytes as N210's Paged backing, copy the complete initialized graph outside timing, retain the original owner, then swap Backing owners into the same live FFT object and restore. No production fields or execution branches are necessary, and no allocation/drop occurs between replay phases. Existing swap validation intentionally rejects different backing layouts, so a dedicated tuning-only prepared-owner handle would need to validate the equal byte span and every descriptor/coefficient bit. Do not shrink to4160 in the same experiment; that also changes allocation size. Record the naturally obtained low-page offset and do not retry for a favorable one. This moves descriptors and coefficients onto different pages together, so it cannot isolate descriptor cache behavior or physical causes.

Chronology matters: N4096's loss predates the latest FourStep canonicalization; N210's Estimate loss is new. Keep their diagnoses separate. No source edits, compilation, disassembly, or benchmarks were performed for this review.
